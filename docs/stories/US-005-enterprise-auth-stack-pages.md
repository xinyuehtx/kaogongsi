## 用户故事

> **作为**要把这套评测平台落到团队里的负责人，
> **我想要**一键在本地拉起完整服务、有账号和角色、能按项目授权，并有一个对外可访问的介绍+文档+演示站点，
> **以便于**不同角色各看各的、数据按授权隔离，且新人能自助上手。

## 验收标准（Given / When / Then）

### AC-1 一键自包含全栈
- **当** 我执行 `docker compose up`（或 `pnpm stack:up`）
- **那么** 后端 + 前端同时起来，打开 http://localhost:8080 可用；账号数据重启不丢（命名卷持久化）

### AC-2 注册与角色
- **假设** 全新部署
- **当** 第一个人注册
- **那么** 他成为**管理员**；之后公开注册默认最小权限（BI），管理员可在管理台调整角色

### AC-3 项目授权隔离
- **假设** 我给某 BI 用户只授权「飞书文档」项目
- **当** 该用户登录
- **那么** 他只看得到被授权的项目；越权访问其他项目数据被拒（401/403）

### AC-4 角色决定可见分区
- **当** 财务登录看报告
- **那么** 只见财务/归因/依据分区；技术见质量/护栏/过程质量等；管理员见全部

### AC-5 管理台
- **当** 管理员进入管理台
- **那么** 可新建用户、改角色、按项目勾选授权（企业版走后端，演示态走浏览器）

### AC-6 对外站点
- **当** 访客打开 GitHub Pages
- **那么** 看到项目介绍、操作文档，并能进 Playground 亲手体验（一键切角色，无需后端）

## 不在本故事内
- SSO/OIDC、刷新令牌吊销、审计日志、管理端分页
- Postgres（已留 StoragePort 适配位；默认 JSON 文件持久化）

## 演示脚本
1. `pnpm stack:up` → http://localhost:8080 注册（首个=管理员）→ 管理台建「技术/财务/BI」用户并授权。
2. 分别登录各角色，验证可见项目与分区差异。
3. GitHub Pages（或 `VITE_SITE_MODE=pages pnpm --filter @tengxiaohtx/web dev`）：介绍/文档/Playground 一键切角色体验。
4. `pnpm test && pnpm e2e` 全绿。
