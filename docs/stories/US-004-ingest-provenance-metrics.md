## 用户故事

> **作为**看板/报告的使用者，
> **我想要**指标不是拍脑袋的数字，而是**从原始评测信号聚合出来的**、带样本量与置信区间、且能下钻到具体案例，
> **以便于**我知道「改动到底有没有变好」有多可信（P1），失败能追到证据（P2）。

## 验收标准（Given / When / Then）

### AC-1 指标由信号算出
- **假设** 某版本有一批逐案例评测信号（通过/失败）
- **当** 系统计算该版本指标
- **那么** 任务成功率 = 通过率×100，并带**样本量**与 **bootstrap 置信区间**（重复可得同值）

### AC-2 可下钻到证据
- **当** 我要追问某指标
- **那么** 能按指标取到其支撑案例、按案例 id 下钻，并看到血缘与来源（T30）

### AC-3 护栏按阈值自动判定
- **假设** 幻觉率信号命中率越过阈值
- **那么** 该护栏标破线，向上驱动 NO-GO

### AC-4 纯 BI 数据也能进、但不伪装
- **假设** 某来源只有聚合读数（metric-only）
- **那么** 指标照样算出，但**不产生可下钻案例**，报告标「不可下钻」

### AC-5 端到端六层贯通、不回归
- **当** 我跑既有 exec/对比场景
- **那么** 结论与数值一致（现在是从信号一路算到报告），E2E 9 场景全绿

## 不在本故事内
- 真实数据源接入（仍 MockConnector；但 L2/L3 已能消费任何符合契约ⓠ 的信号）
- 成本/延迟的真实分布、pass^k 多 run 估计、分层指标

## 演示脚本
1. `pnpm --filter @tengxiaohtx/metrics test`：看 bootstrap 置信区间、pass^k、Cost-of-Pass 计算。
2. `pnpm --filter @tengxiaohtx/web dev`：dt-sheet v2.0 成功率 72%（=72/100 通过信号聚合）；fs-doc v1.0 幻觉率破线 → NO-GO。
3. `pnpm e2e` 全绿（证明换成六层管道后 UI 零回归）。
