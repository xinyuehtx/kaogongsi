# US-003：让「归因」与「决策」被真正算出来

| | |
|---|---|
| 状态 | **✅ 已完成** |
| 关联 RFC | `docs/rfcs/RFC-003-attribution-decision-engines.md` |
| 受众 | 平台自身（架构可信度）+ 高管/工程师（结论可追溯到证据） |

---

## 用户故事

> **作为**看报告的高管/工程师，
> **我想要**报告里的「归因（技术/产品/运营）」和「门禁（GO/NO-GO/ABSTAIN）」是**从证据算出来的**、而不是写死的，
> **以便于**我信任结论、能追问「凭什么这么归因/这么判」，并且换了数据它会跟着变。

## 验收标准（Given / When / Then）

### AC-1 归因随证据变化
- **假设** 某版本护栏破线（幻觉率失败案例多）
- **当** 我看该版本报告
- **那么** 归因明显偏向**技术侧**、置信度更高；换一个健康版本，归因回落到先验分布

### AC-2 归因必有据
- **当** 我看归因任一责任方
- **那么** 它都挂着支撑指标与案例（无案例的纯 BI 数据只给粗粒度且标「不可下钻」）

### AC-3 决策由归因+护栏算出
- **假设** 护栏破线
- **那么** 门禁自动判为 **NO-GO** 并点名破线指标；护栏健康且达阈则 **GO**；证据不足则 **ABSTAIN**

### AC-4 归因与决策是两步、可分别演进
- **当** 我看架构/代码
- **那么** 归因（L4）与决策（L5）是**两个独立包、两道契约**，各自可测、可替换；连接器只提供证据，不做归因/决策

### AC-5 端到端不回归
- **当** 我跑既有 exec/对比场景
- **那么** 页面结构与结论一致（GO/NO-GO/不可下钻等），只是结论现在是算出来的（E2E 9 场景全绿）

## 不在本故事内
- L3 指标从原始样本计算（Cost-of-Pass/pass^k/CI）、L2 真实血缘图、反事实验证。
- 权重/责任方映射的可配置化。

## 演示脚本
1. `pnpm --filter @kaogongsi/web dev` → dt-sheet v2.0（健康）归因≈先验、GO；切 v1.0（较弱）归因随失败案例重分布、ABSTAIN。
2. fs-doc v1.0（幻觉率破线）→ 归因偏技术、门禁 NO-GO、点名幻觉率。
3. `pnpm --filter @kaogongsi/l4-attribution test` / `l5-decision test` 各自独立绿。
4. `pnpm e2e` 全绿（证明换成计算管道后 UI 零回归）。
